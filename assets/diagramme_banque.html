Banque de mémoire hors contexte pour LM 350M — le mécanisme

D'après SPEC_MEMOIRE_V2 — édition lissée du 2026-08-03 (claim validé 2026-07-31), verdicts au 2026-08-04 (grille §2.4 du 08-03, phase 11 dépouillée 22/22 le 08-04). Un seul store, un seul geste d'écriture, deux régimes de lecture. Ce qui est TRANCHÉ, ce qui est EN COURS et ce qui est ÉCONOMISÉ est marqué comme tel.

Appris — read kvproj (WK′/WV′ + fréquences d'âge), retriever Wq, copy-head, politique <think>/retrieve (GRPO) Procédural — curseur Δn, sélection SIF ∪ copy_mask, dédup en ligne, FIFO + propagation, rotations (aucun paramètre) État persistant — la banque : un tenseur constant de lignes natives RESET — la fenêtre est jetée, la banque traverse
Règle d'adjudication (actée 08-03, audit des absolus) — tout arbitrage d'architecture se juge en nll_live ABSOLU apparié + grade décodé + r@1. Le Δnll intra-modèle est DÉPRÉCIÉ comme juge : sur le même carré il a gonflé un gagnant (part bait +0,044 de kvproj) et masqué un concurrent (dual_heads, meilleur en absolu, puni pour son meilleur plancher ablaté). Il reste une sonde de conditionnement (paires contrastives), jamais un juge.

1. Vue d'ensemble — un cycle : write → store → deux lectures

La fenêtre de contexte est bornée et identique pour tous les bras. La banque est hors de la fenêtre : elle ne coûte aucun token de fenêtre (elle coûte des forwards, comptabilisés au §4).

2. Zoom write — curseur Δn, sélection, dédup, puis APPEND (le slot structuré est mort)

Le slot (clé, surface, gist) est remplacé (spec §2.2) : chaque ligne est littéralement un vecteur du modèle, de largeur d = d_model — plus de clé stockée (la clé est une fonction, calculée au read), plus de dichotomie de format. Rien n'est produit par un réseau appris : le write est une sélection (labo jouet ph.7 — tout readout appris est mort, seule l'injection native cite). L'écrasement choisi est remplacé par append + décalage + propagation.

2bis. Métadonnées = rotations sur plans réservés (BankRot) — verdicts de la phase 11

Les métadonnées ne sont pas des champs : quand / qui / quel canal sont des rotations élémentaires des clés, le contenu restant le vecteur natif intact. Trois familles étaient prévues ; la phase 11 (22 cellules zzr*, dépouillée le 2026-08-04, 0 échec) en a tranché deux et invalidé un examen.

3. Zoom lecture — deux régimes sur un seul store

Même banque, deux chemins qui ne consomment pas la même nature de ligne et ne servent pas la même fonction. La lecture est la seule classe de fonctions apprise du design — et c'est de l'attention. Verdict du carré factoriel (08-03, re-jugé en absolu) : kvproj ADOPTÉ (nll_live −0,165 ± SE 0,053, t 3,1 vs kv_append ; exploitation réelle du budget m : 3,86 → 3,35 de m1 à m8) ; dual_heads DOMINÉ coût-ajusté (meilleur en absolu à chaque m mais +0,048 = bruit, double coût, params non appariés) ; bank-q INVALIDÉ (fuite non-causale : les lanes voyaient le futur teacher-forcé) ; fast-weight read retiré (ph.10).

4. Le protocole central — sessions à travers les RESET

Une « session » = plusieurs fenêtres séparées par des resets. Le token RESET jette la fenêtre (jamais la banque). Les deux ailes (conditionnement, rappel exact) sont mesurées après n resets, en fonction de n — le conditionnement par paires contrastives Δnll comme sonde, le rappel par le grade décodé (jamais le Δnll : règle d'adjudication ci-dessus).

5. La greffe — points d'attache exacts sur le stack 350M

Dimensions du backbone lues dans configs/sft_recall_350m_copy.yaml et le code (model.py, memory.py, rti.py, rti_copy.py, rti_policy.py) : d_model 768 · 12 couches · 12 têtes × d_head 64 · MoE 4+1 top-2, d_ff 1536 · n_hc 2 · max_mem 8 · max_seq_len 640 · vocab SmolLM2-135M. Ce qui change par rapport au ckpt déployé : le read n'est plus un read fast-weight (banque = jeu de poids, mem_dim 512) — c'est une attention kvproj sur des lignes natives de largeur d (mem_dim = nombre de lignes par tour, 16 mesuré en S16). Plan de greffe : greffe + SFT sur le ckpt 350M existant d'abord (fixe S10 le point de tap, S19 les couches lectrices, le tag-curseur ; ablation cascade ON/OFF per S20), puis from-scratch ENSUITE sur spec gelée, avec un mid-training élargi (ChatML + instructions + dépendance mémoire via protocole RESET + corpus agentique + curriculum de longueur).
