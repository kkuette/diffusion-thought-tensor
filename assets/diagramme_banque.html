Banque de mémoire hors contexte pour LM 350M — le mécanisme

D'après SPEC_MEMOIRE_V2 §1–3 (validée 2026-07-31) et le kill-test 3 du 2026-08-01. Un seul store, un seul geste d'écriture, deux régimes de lecture.

Appris — retriever Wq, copy-head, politique write / choix de slot (GRPO) Procédural — clé SIF, sélection de surface, gist SIF, FIFO d'amorçage (aucun paramètre) État persistant — la banque et ses slots RESET — la fenêtre est jetée, la banque traverse

1. Vue d'ensemble — un cycle : write → store → deux lectures

La fenêtre de contexte est bornée et identique pour tous les bras. La banque est hors de la fenêtre : elle ne coûte aucun token de fenêtre (elle coûte des forwards, comptabilisés au §4).

2. Zoom write — le slot structuré (clé, surface, gist) et l'écrasement

Un seul geste, trois composantes, trois provenances différentes. Rien de tout cela n'est produit par un réseau appris : la sélection est procédurale (labo jouet ph.7 — tout readout appris est mort, seule l'injection native cite).

3. Zoom lecture — deux régimes sur un seul store

Même banque, deux chemins qui ne consomment pas la même composante et ne servent pas la même fonction.

4. Le protocole central — sessions à travers les RESET

Une « session » = plusieurs fenêtres séparées par des resets. Le token RESET jette la fenêtre (jamais la banque). Les deux ailes (conditionnement Δnll, rappel exact) sont mesurées après n resets, en fonction de n.

5. La greffe — points d'attache exacts sur le stack 350M

Valeurs lues dans configs/sft_recall_350m_copy.yaml et le code (model.py, cascade.py, memory.py, rti.py, rti_copy.py, rti_policy.py). d_model 768 · 12 couches · 12 têtes × d_head 64 · MoE 4+1 top-2, d_ff 1536 · n_hc 2 · mem_dim 512 · max_mem 8 · max_seq_len 640 · vocab SmolLM2-135M. Attention : le read de la banque n'est pas une cross-attention — c'est un read fast-weight (la banque est un jeu de POIDS).

5bis. Le forward déployé (sans cascade) — ce qui tourne vraiment dans le run copy

Le sous-ensemble vivant du panneau 5. cascade_depth: 0, layer_banks tout à None, write=False : aucune banque n'entre dans le stack. Le seul état persistant est la LaneBank RTI, hors du graphe, et la boucle passe par le préfixe du forward suivant.
